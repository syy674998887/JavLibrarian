JavLibrarian organizes JAV media libraries on NAS systems: it recognizes catalog numbers from folder names, queries JavBus and JavDB, and generates NFO files and artwork for local media centers. UGREEN UGOS reads the filename-matched NFO files (with “prefer local metadata” enabled), while Emby, Jellyfin, and Kodi use the folder-level `movie.nfo`.

## Installation

```bash
git clone https://github.com/syy674998887/JavLibrarian.git
cd JavLibrarian
uv sync
uv run javlibrarian --help
```

Requires Python 3.11+. Commands are the same on macOS, Windows, and Linux.

## Library layout

`--dir` sets the media-library root. JavLibrarian scans only its immediate subdirectories, recognizes catalog numbers from their names, and does not recurse further. Hidden directories are ignored. `inspect` reports names with no recognized catalog number; `scrape` and both `rename-*` commands skip them.

```text
/path/to/JAV/
├── SONE-035/
│   └── SONE-035.mp4
├── IPVR-256-C/
│   └── IPVR-256-C.mkv
└── FC2-PPV-1234567/
    └── FC2-PPV-1234567.mp4
```

Catalog-number normalization affects only queries and NFO output. Folder semantics such as `-C`, `-U`, `-UC`, and `-leak` become NFO tags; `scrape` does not rename folders or videos.

Only video files directly inside these subdirectories are recognized. Extensions are case-insensitive:

`.mp4` `.mkv` `.avi` `.wmv` `.mov` `.m4v` `.ts` `.iso` `.rmvb` `.flv`

Video filenames do not need to match their directory name. Multiple supported videos in one directory share its metadata and each receive a filename-matched NFO.

## Command reference

```bash
uv run javlibrarian COMMAND [OPTIONS]
```

| Command | Purpose |
| --- | --- |
| `scrape` | Query metadata and generate NFO files and artwork |
| `inspect` | Show the query ID and tags recognized from each folder name |
| `rename-folders` | Normalize immediate-subdirectory names |
| `rename-videos` | Clean video and matching sidecar filenames |
| `undo-folders` | Roll back the latest batch of folder renames |
| `undo-videos` | Roll back the latest batch of video renames |

> [!IMPORTANT]
> `inspect` does not use the network or write to disk. `scrape` uses the network and writes NFO files and artwork, but never deletes or rewrites videos. The two rename and two rollback commands preview by default and require `--apply` to execute.

### Directory and selection

| Option | Commands | Purpose |
| --- | --- | --- |
| `--dir PATH` | All | Media-library root; falls back to `JAVLIBRARIAN_DIR` when omitted |
| `--limit N` | `scrape`, `inspect`, both `rename-*` commands | After `--only` filtering, process at most the first N folders in case-insensitive name order; `0` (default) means all |
| `--only NAME` | `scrape`, `inspect`, both `rename-*` commands | Process only the immediate folder for a specified catalog number; `NAME` must be the complete, case-sensitive folder name and may be repeated |

### Scraping

These options belong only to `scrape`:

| Option | Purpose |
| --- | --- |
| `--force` | Reprocess folders with an existing `movie.nfo` and replace same-named NFO/artwork successfully generated by this run |
| `--page-delay SECONDS` | Base interval between consecutive page requests to the same metadata source; default `5.0` seconds. JavBus and JavDB are timed separately |
| `--image-delay SECONDS` | Base interval between consecutive requests to the same image host; default `2.0` seconds |
| `--delay SECONDS` | Interval between titles scraped over the network; default `10.0` seconds |
| `-v`, `--verbose` | Show request waits, inter-title waits, adaptive slowdown, and retries |

Delay values must be finite and non-negative. Zero disables only the corresponding base interval; retry backoff may still wait.

HTTP 408, 429, 500, 502, 503, 504 and network exceptions are retried for at most five attempts. Backoff starts at 10 seconds, doubles, and caps at 300 seconds; a numeric `Retry-After` on 429 takes precedence. Every 429 or 503 multiplies the affected nonzero host/request-type base interval by 1.5, capped at 30 seconds. Other 4xx responses are not retried.

### Rename and rollback

| Option | Commands | Purpose |
| --- | --- | --- |
| `--apply` | Both `rename-*` and both `undo-*` commands | Execute the currently displayed rename or rollback plan |
| `--journal PATH` | Both `rename-*` and the corresponding `undo-*` command | Set the rollback journal; rollback uses the same file written by the rename command |

Each `undo-*` invocation handles only the latest batch in its journal; run it again to continue with the preceding batch.

## Generated files

```text
SONE-035/
├── SONE-035.mp4
├── SONE-035.nfo
├── movie.nfo
├── fanart.jpg
├── poster.jpg
└── Samples/
    ├── sample1.jpg
    └── ...
```

| File | Role |
| --- | --- |
| `{video}.nfo` | Media centers that read filename-matched NFO files, such as UGREEN UGOS |
| `movie.nfo` | Folder-level NFO for Emby, Jellyfin, and Kodi; also the scrape-completion marker |
| `fanart.jpg` | Landscape cover |
| `poster.jpg` | Portrait poster |
| `Samples/` | Page stills |

After artwork and filename-matched NFO files are complete, `movie.nfo` is written last and atomically. A folder without it after an interrupted run is processed again on the next run.

## Metadata sources and merge rules

Metadata comes from [JavBus](https://www.javbus.com) and [JavDB](https://javdb.com). A single valid source is used directly. When both match, JavBus is the primary record and JavDB supplies missing fields and alternate artwork.

### Source validation

A source result is accepted only when its reported catalog number matches the locally normalized number. For ordinary letter-and-number catalog numbers, comparison is case-insensitive, ignores separators, and ignores leading zeros in the numeric part; for example, `IPVR-256` and `ipvr_0256` are equivalent. If neither source has a valid result or processing raises an error, the folder is reported as failed.

### Field merging

| Data | Merge rule |
| --- | --- |
| Titles | Write the JavBus title as `originaltitle`; use the JavDB title as the display title when it contains no Japanese kana, otherwise keep the primary-record title |
| Release date, runtime, studio, label, director, series | Keep existing JavBus values and use JavDB only to fill blanks |
| Genres | Union and deduplicate both lists, preserving JavBus order first |
| Actors | Use JavBus actors and thumbnails; use the JavDB actress list only when JavBus has no actors |
| Cover | Use JavBus first and try the JavDB cover if that download fails |
| Stills | Use JavBus first with same-index JavDB images as alternates; use JavDB when JavBus has no stills |
| Source marker | Record the actual match as `javbus`, `javdb`, or `javbus+javdb` |

### Artwork and posters

A failed download, an undecodable image, or an image with a short edge below 200 pixels does not replace an existing file; an alternate source is tried when available. Valid images are written only after temporary-file validation.

- Standard titles crop the rightmost 47.5% of the landscape cover into `poster.jpg`.
- VR titles first use DMM `ps.jpg` as a reference to identify a portrait cover among the stills. Without a usable reference, the first portrait still is selected, then landscape-cover cropping is used as the final fallback.

## Folder and video renaming

Folder and video workflows use independent rollback journals. Each rename action is written atomically to its journal before the filesystem is touched. Rollback verifies the media-library root and distinguishes completed, untouched, and partially completed entries.

A video, its matching subtitles (including language-tagged ones such as `SONE-035.chs.srt`), and filename-matched NFO are handled as one group; folder-level `movie.nfo` is not renamed. If any target is occupied, the whole group is skipped. Rollback never overwrites an existing file.

## Privacy

- Scraping sends catalog-number queries to JavBus and JavDB and downloads images referenced by their pages.
- Rename journals contain local paths and media filenames. The default journal paths are gitignored; protect custom paths separately.

## Testing

```bash
uv run --group test pytest
```

The test suite is fully offline and does not contact live metadata sites.

## Known limitations

- Parsers depend on the current HTML of JavBus and JavDB.
- Requests are serial and conservative; large libraries take time.
